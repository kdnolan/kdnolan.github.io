Summary

The short version

The good news. Nothing indicates that anyone got into our systems. No viruses were detected. Twenty known software holes on one Windows 11 machine were closed by updates during the week, which shows updating works when it is allowed to run.

The bad news. The old Windows 10 computer (tigswin10) has 32 known security holes that have not been fixed, 20 of them rated critical. Windows 10 stopped receiving free security updates in October 2025, so this will only get worse. Two Windows 11 machines scored poorly on a standard checklist of safe settings: no lock-out after repeated wrong passwords, the built-in guest account still enabled, remote command access left on, and so on.

Things to check. Two Macs show "hidden" network ports, which is often a false alarm on Macs but should be confirmed. The monitoring software itself lost contact with computers 121 times, so there were gaps in what we could see. On one older Windows PC, the antivirus policy settings were changed 28 times, which is worth a quick look to confirm it was Windows itself doing it.

Act now

Software updates and known holes

Every piece of software has flaws. When a flaw is discovered it gets a public reference number (a "CVE") and a severity rating, and the maker releases a fix. Our monitoring compares what is installed against that public list.

One machine stands out. tigswin10 runs Windows 10 Pro and has 32 known, unfixed holes: 20 rated critical (the highest level) and 12 rated high. Because Microsoft ended free Windows 10 support in October 2025, no fixes are coming for this computer unless it is upgraded to Windows 11 or enrolled in paid extended updates. A criminal who gets a foothold on our network would find this the easiest machine to take over.

Elsewhere, updates are working. On a Windows 11 Home machine, 20 previously-reported holes were closed during the week because updates installed. That is exactly what we want to see.

Act now

Safe-settings checklist

Independent security experts publish a checklist of recommended settings for each operating system (the "CIS Benchmark"). Our monitoring checks each computer against it and gives a percentage score. Think of it like a car safety inspection: the car may drive fine, but the inspector still wants the seatbelts to work.

Our Windows 11 machines scored poorly. kmanwin11new scored 25%, and DAZWIN11 fails the same checks. Around 40 individual settings were flagged. In everyday terms, the ones that matter most are:

• Accounts are not locked after repeated wrong passwords, so a password-guessing attack can run all day.
• The built-in Guest account is still enabled and the Administrator and Guest accounts still have their default names, which makes them easy targets.
• Remote command access ("Remote Shell") and basic, unencrypted logins to Windows management tools are allowed.
• Old passwords can be reused (no password history), and blank passwords are not restricted to the keyboard in front of the machine.
• Windows is allowed to send unencrypted network traffic to management services.

None of these settings is difficult or expensive to change. Most take a few minutes each and can be applied to all Windows machines at once.

Watch

Viruses and hidden activity

The monitoring runs three kinds of malware check: scanning files against known virus signatures, checking suspicious files against an online database, and looking for things a computer is trying to hide from its owner (a classic sign of a "rootkit").

No viruses were found. The file and online-database scans produced no hits during the week.

Two Macs reported hidden network ports. A network port is like a numbered door a program listens at. When a program uses a door but that door does not appear in the computer's own list, the monitor calls it "hidden". Mac.lan reported door 55555 hidden 15 times, plus a scatter of others; kmanmacintosh reported one hidden process. On Macs this is frequently a false alarm caused by how macOS reports network activity, but it is also exactly what real hidden software looks like, so someone should confirm which program is using port 55555.

Fine

Changes to files and system settings

This is where most of the week's 7,500 events came from, and almost all of it is noise. The monitor records every change to important files and to the Windows registry (the database where Windows keeps its own settings). Windows changes its own registry constantly: backup snapshots, clock synchronisation, firewall bookkeeping and app usage tracking account for the vast majority of the roughly 5,000 change alerts.

One thing earned a second look. On Kman_Win_Old, the Windows Defender antivirus policy area was modified 28 times and firewall rules were edited and deleted. Windows Update does this itself, so it is probably benign, but antivirus and firewall settings are what an attacker changes first, so a quick confirmation is sensible.

Separately, computers opened or closed network ports 262 times and 24 new Windows services were created. Both are normal when software is installed or updated, and the counts are in line with a week that included Windows updates.

Watch

Logins, accounts and monitoring coverage

Logins look normal. 16 successful Windows logins, routine Mac screen locks and unlocks, and only 2 failed attempts with a wrong password (on kmanwin11new). Two failures in a week is what forgetting a password looks like, not an attack.

Account changes were few but should be explainable. On DAZWIN11, a user account was changed 4 times and, on kmanwin11new, one account was disabled or deleted and group memberships changed. These are exactly the events a business should be able to explain: if nobody on the team remembers making these changes, that is the moment to dig deeper.

The monitor itself went blind at times. The monitoring agent lost its connection to computers 121 times and was stopped 5 times (twice on DAZWIN11). Laptops going to sleep or leaving the office cause most disconnections, but each gap is a period where we could not see what happened. If a machine's agent is being stopped by hand, that should be understood.

Context

What the "compliance" reports mean

Four of the ten reports carry the names of formal rulebooks: HIPAA, GDPR, NIST 800-53 and TSC. They do not mean we are being audited, and they do not contain new findings. The monitoring simply tags each alert with the rulebook clauses it relates to, so the same 7,500 events are re-sorted four ways. Nearly every tag points back to the routine registry changes described above. The rulebooks are useful as a shared vocabulary if we ever need to show a partner or funder how we look after data.

HIPAA · 164.312

US health-data privacy law

Our alerts were tagged mostly to its "integrity" and "audit controls" clauses: keep records of changes and be able to tell if data was altered.

GDPR · Art. 5, 32, 35

EU personal-data regulation

Tags related to keeping systems reliable, detecting break-ins, and tracking who has admin access. The Australian equivalent is the Privacy Act.

NIST 800-53 · SI-7, CM-1, AU-6

US government security controls

Clauses about checking software has not been tampered with, managing configuration, and reviewing logs.

TSC · CC6, CC7

Trust criteria behind SOC 2 audits

Controls for restricting access, detecting anomalies and responding to incidents. Often asked about by larger partners.

Priorities

What to do next

In order of importance. The first three would move this week's verdict from amber to green.

  1. Upgrade or retire the Windows 10 computer (tigswin10)

    It has 32 unpatched holes and no more free fixes are coming. Upgrade it to Windows 11 if the hardware allows, replace it, or keep it off the network until then.

    Owner: IT · Effort: an afternoon, or a new PC

  2. Apply the basic safe settings to all Windows PCs

    Lock accounts after 5 wrong passwords for 15 minutes, disable the Guest account, rename the Administrator account, turn off Remote Shell and basic authentication, and require 24 unique passwords before reuse. Start with kmanwin11new and DAZWIN11, then re-check the score.

    Owner: IT · Effort: 1–2 hours, repeatable

  3. Confirm what is using port 55555 on the Macs

    Ask the owners of Mac.lan and kmanmacintosh which apps they run, then check the port. If it is a known app (screen sharing, sync tools and games commonly use high port numbers) mark it as expected so it stops alerting.

    Owner: IT · Effort: 30 minutes

  4. Explain the account changes and agent stops on DAZWIN11 and kmanwin11new

    Someone should recognise the 4 account changes, the deleted account and the two times the monitoring agent was stopped. If nobody does, treat it as a possible intrusion and investigate.

    Owner: device owners · Effort: a conversation

  5. Reduce monitoring blind spots

    121 disconnections in a week is high for 8 machines. Check that agents start automatically and are not being closed by users, and consider excluding home laptops from the count if they are expected to be offline.

    Owner: IT · Effort: 1 hour

  6. Glance at Defender policy changes on Kman_Win_Old

    Confirm the 28 antivirus policy changes and the firewall edits line up with Windows Update activity, then move on.

    Owner: IT · Effort: 15 minutes
Reference

Jargon, translated

Agent
A small program installed on each computer that reports back to the monitoring system. When it "disconnects", we lose sight of that computer.
Alert level
A 0–15 severity number. Under 5 is routine, 7 is worth attention, 10+ is serious. Most of our week sat at level 5.
CVE
A public reference number for a known software flaw, like a recall notice for cars. Each comes with a severity rating.
CIS Benchmark
An independent, widely-used checklist of recommended security settings for Windows and Mac. Reported as a percentage passed.
File integrity monitoring
Watching important files and settings and raising an alert whenever one changes, so tampering can be spotted.
Registry
Windows' internal settings database. Windows edits it constantly, which is why it generates most of our alerts.
Rootkit / hidden port
Software that conceals itself from the computer's own tools. "Hidden port" means a network connection the computer did not admit to.
MITRE ATT&CK
A catalogue of the tactics attackers use. The monitor tags alerts with the tactic they could be part of, for context.

How were the traffic lights decided?

"Act now" was given where an attacker could directly exploit the finding today (unpatched critical flaws; missing lock-out and open remote access). "Watch" covers findings that need a human to confirm they are expected. "Fine" means the alerts were routine operating-system behaviour with no security implication. The judgement is ours, based on the counts in the reports, not a score produced by the monitoring tool.

What is not in these reports?

Email and phishing, cloud services (Google Workspace, Microsoft 365, website hosting), phones and tablets, and backups are outside what these ten reports cover. A complete picture of the organisation's security would include those.
