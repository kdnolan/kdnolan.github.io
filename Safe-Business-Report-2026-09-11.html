Summary

The short version

The good news. Nothing indicates anyone got into our systems and no viruses were detected. The biggest improvement is monitoring coverage: the agents lost contact only 7 times this week, down from 121, so we now have a near-complete picture. Hidden processes have gone from one Mac to none.

The bad news. The two "act now" items from last week are unchanged. The Windows 10 computer (tigswin10) showed no sign of being updated, so its 32 known holes are still open. DAZWIN11 re-scored 26% on the safe-settings checklist (25% last week), and no setting on either Windows 11 machine was seen changing to "passed", so the lockout, guest account and remote access weaknesses remain.

New this week. On the Mac tigs, Remote Login (SSH) was switched on, which opens a door for remote control of that machine, and it scored 54% on the Mac safe-settings checklist. kmanmacintosh ran 65 commands as the all-powerful root account, up from a handful last week. DAZWIN11 logged 10 user account changes, and kman had 5 wrong-password login attempts. All of these have innocent explanations if someone on the team recognises them.

Act now

Software updates and known holes

Every piece of software has flaws. When one is discovered it gets a public reference number (a "CVE") and a severity rating, and the maker releases a fix. Our monitoring raises an alert when a new hole is found on a computer and another when a hole is closed.

This week there were no vulnerability alerts at all. That means no new holes were discovered, but also that none were fixed. Last week 20 holes were closed on a Windows 11 machine by updates; this week nothing similar happened. In particular there is no sign that tigswin10 received any update, so its 32 known holes, 20 of them critical, are still open. Because Windows 10 no longer gets free fixes, they will stay open until the machine is upgraded, replaced or taken off the network.

To be clear about the limits of what we can see: the alerts only fire when something changes. A quiet week here is not the same as a clean bill of health.

Act now

Safe-settings checklist

Independent experts publish a checklist of recommended settings for each operating system (the "CIS Benchmark"). Our monitoring scores each computer against it and raises an alert whenever a setting flips between pass and fail.

Windows: no progress. DAZWIN11 was re-scored twice this week at 25% and 26%. The only setting seen changing was "automatic logon", which flipped from failed to passed and back again, suggesting someone was experimenting with it. None of the important items from last week (account lockout, Guest account, Remote Shell, unencrypted logins, password reuse) was seen changing to passed on either Windows 11 machine.

Mac: a new item. The Mac tigs was checked against the macOS checklist for the first time and scored 54%. One change stands out: "Remote Login" moved from passed to failed, meaning SSH remote access to that Mac was turned on during the week. That is fine if someone did it deliberately and it has a strong password or key, and a real risk if not, because it lets anyone on the network attempt to log in to that machine.

Watch

Viruses and hidden activity

The monitoring scans files against known virus signatures and looks for things a computer is trying to hide from its owner (a classic sign of a "rootkit").

No viruses were found, and the hidden process reported on kmanmacintosh last week has gone.

All three Macs now report hidden network ports, up from two. Mac.lan reported door 55555 hidden 17 times, almost identical to last week's 15, plus a scatter of other high-numbered ports; kmanmacintosh reported a similar number and tigs once. The steady, repeating pattern on the same port strongly suggests a legitimate app (screen sharing, sync and games use ports like this) rather than something malicious, but it has now been flagged two weeks running and should be identified so it can be marked as expected.

Fine

Changes to files and system settings

As last week, this is where most events come from and almost all of it is noise: Windows constantly edits its own settings database (the registry) for backups, clock sync, firewall bookkeeping and app tracking. About 4,400 registry change alerts this week, in line with last week's 4,800.

The one number that jumped is network ports being opened or closed: 881, up from 262. Almost all of it is the two Macs Mac.lan (515) and tigs (343). Macs doing this at that rate usually means a chatty app such as a browser, cloud sync or a media tool, and it lines up with the hidden-port reports above, so identifying that app answers both questions at once.

The antivirus (Defender) policy area was modified 26 times on Kman_Win_Old and 24 times on kmanwin11new, the same pattern as last week and consistent with Windows Update doing its housekeeping. Only 2 new Windows services were created (24 last week). Firewall rules were added and removed on DAZWIN11 and kman, which typically accompanies software installs.

Watch

Logins, accounts and monitoring coverage

Monitoring coverage is the week's big win. The agents lost contact with computers only 7 times, down from 121, and none was stopped by hand. Whatever changed, keep it that way: it means this report is based on a near-complete picture rather than one with gaps.

Logins. 20 successful Windows logins and 5 failed attempts with a wrong password, all on kman. Five in a week on one machine still looks like a person mistyping rather than an attack, especially on a machine that appears to have been freshly set up, but it is more than last week's 2.

Administrator activity went up sharply. On kmanmacintosh, 65 commands were run as root and 14 more with administrator rights, compared with 9 in total across everything last week. Root is the all-powerful account; a burst like this usually means someone was installing or configuring software, and is completely normal if that was the case. On DAZWIN11, 10 user account changes were recorded (4 last week) along with 3 audit failures. These are exactly the events a business should be able to explain: if the people who use those machines recognise them, close the item; if not, dig deeper.

Context

What the "compliance" reports mean

Three of this week's reports carry the names of formal rulebooks: NIST 800-53, GDPR and TSC. As last week, they contain no new findings; the monitoring simply tags each alert with the rulebook clauses it relates to, so the same events are re-sorted three ways. Nearly every tag points back to the routine registry changes and the Macs' port activity described above. They are useful as a shared vocabulary if we ever need to show a partner or funder how we look after data.

NIST 800-53 · SI-7, AU-6, AU-14

US government security controls

Checking software has not been tampered with, and reviewing logs. The Macs' port activity dominates the audit-log clauses this week.

GDPR · Art. 5, 32, 35

EU personal-data regulation

Keeping systems reliable, detecting break-ins, and tracking who has admin access. The Australian equivalent is the Privacy Act.

TSC · CC6, CC7

Trust criteria behind SOC 2 audits

Restricting access, detecting anomalies and responding to incidents. Often asked about by larger partners.

In order of importance. Items 1 and 2 are carried over from last week unchanged; the first three would move the verdict to green.

    Second week running with 32 unpatched holes and no updates observed. Upgrade it to Windows 11 if the hardware allows, replace it, or keep it off the network until then.

    Owner: IT · Carried over · Effort: an afternoon, or a new PC

Reference

Jargon, translated

Agent
A small program installed on each computer that reports back to the monitoring system. When it "disconnects", we lose sight of that computer.
CVE
A public reference number for a known software flaw, like a recall notice for cars. Each comes with a severity rating.
CIS Benchmark
An independent, widely-used checklist of recommended security settings for Windows and Mac. Reported as a percentage passed.
Remote Login / SSH
A way to log in to a computer from another machine over the network. Useful for admins; a risk if left on without a strong password.
Root / sudo
The all-powerful administrator account on Macs. "sudo" is the command that runs something as root. Normal during installs; unusual in bulk.
Registry
Windows' internal settings database. Windows edits it constantly, which is why it generates most alerts.
Rootkit / hidden port
Software that conceals itself from the computer's own tools. "Hidden port" means a network connection the computer did not admit to.
Port
A numbered door a program uses to talk on the network. Programs open and close them constantly; a sudden jump usually means a new or chatty app.
