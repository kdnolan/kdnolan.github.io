Browsers: Edge fixed, Firefox exposed

Web browsers are the most-attacked software on any computer, because they open whatever the internet sends them. Both major browsers had security news in the last 24 hours.

Microsoft Edge: 12 holes closed. Six known flaws in Edge, and the same six in the Edge WebView component that other apps use to show web content, were marked as fixed after an update installed. No action needed.

Firefox: 8 closed, 26 opened. An update fixed 8 older Firefox holes, but Mozilla's new advisory lists 26 further holes affecting the version now installed: 12 critical, 7 high and 7 medium. In practice this means Firefox is one release behind and the current release is the fix. Open Firefox, go to Help → About Firefox, and let it update; then restart the browser. Do this on every machine that has Firefox.

Windows 11 Pro: 1 new hole. One new medium-severity flaw (CVE-2026-45585) was announced for Windows 11 Pro. Windows Update will pick it up on its normal schedule.

A note on our wording. The monitoring rates holes on a scale where level 13 is "critical", level 10 "high" and level 7 "medium". In the two weekly reports we described the Windows 10 machine's level-10 holes as "critical"; by this scale they are "high" (still serious, still unfixable on Windows 10). Today's Firefox holes are the first genuinely critical-rated ones we have seen. We will use the monitoring's own scale from here on.

Logins and account changes

In one day: 22 successful Windows logins, 6 failed attempts with a wrong password, 13 changes to user accounts (rated level 8, one of the higher ratings), 18 Windows audit failures (Windows recording that something was denied), 21 logins that were granted special privileges, and 8 system shutdowns. Two new Windows services were also created and 5 application errors were logged at level 9.

Read together, this is either a person doing a lot of admin work on the Windows machines (creating or changing accounts, installing software, rebooting, occasionally mistyping a password), or something we would very much want to know about. The two look identical in the logs. The difference is whether someone on the team says "yes, that was me, yesterday afternoon".

The Macs: a network storm and a midnight update

878 port open/close events in 24 hours. A network port is a numbered door a program uses to talk on the network. Last week's total was 881, which means almost all of the week's Mac network churn happened yesterday. This is the same machines (Mac.lan and tigs) and the same pattern as the recurring hidden port 55555, which was reported 4 more times. Something on those Macs, most likely a sync, sharing or media app, was working very hard yesterday. It is not a sign of compromise on its own, but it is the third report in a row to flag it and it should now be identified.

A macOS update installed overnight. At 01:22 to 01:23 on 11 September, one Mac granted a batch of system permissions to a dozen of Apple's own background services (Maps, Screen Time, Game Center and so on) within sixty seconds. That is exactly what the first boot after a macOS update looks like, and it explains some of the reboot and screen-lock activity. Nothing to do.

Administrator use on the Macs was light: 8 root commands and 2 admin commands, well down from 79 last week.

The Windows 10 PC finally updated something

For two weeks tigswin10 showed no update activity at all. Yesterday it did. The registry changes on that machine are almost all in the Windows Defender antivirus services (the core service, the network inspection service, the boot and filter drivers) and in Microsoft Edge, with a Windows servicing-stack run creating restore points. In plain terms: its antivirus engine and its browser were both updated overnight, and its firewall rules were rewritten as part of that, which is normal.

This matters because it shows the machine is still receiving the updates Microsoft does still ship for Windows 10 (antivirus definitions and Edge), even though the operating system itself no longer gets security fixes. The 32 operating-system holes from the weekly reports are unchanged. Upgrading or retiring that machine remains the top item on the weekly to-do list.

The other Windows machines showed only the usual background housekeeping (about 600 registry changes across four PCs, mostly backup-snapshot and clock bookkeeping).

Notes

About this special report

Which source reports were used?

Five 24-hour module reports: Threat hunting, Malware detection, File integrity monitoring, MITRE ATT&CK and IT hygiene, each covering roughly 12:28 on 10 September to 12:28 on 11 September 2026. Alerts from the monitoring server itself are excluded. No compliance reports (which give per-machine breakdowns) and no router logs were included, so some counts cannot be attributed to a specific computer.

Why a one-day report reads differently

Over a week, routine noise dominates and one busy afternoon disappears into the totals. Over a day, that afternoon is the whole story. That is why several counts here look alarming next to the weekly figures: they are the same kind of activity, concentrated. The right response is to check that the activity was intended, not to assume a problem.

How were the traffic lights decided?

Same fixed rules as the weekly reports: a directly exploitable finding is "Act now" (today: critical browser holes with an easy fix); findings that need a human to confirm they were intended are "Watch"; routine or beneficial activity is "Fine".
