Summary

The short version

The good news. Two items that have been on the list since the first report are closed. The Windows 10 computer (tigswin10) has been removed from the network, taking its 32 unfixable holes with it. And the recurring hidden port 55555 on the Macs has been identified as Apple's own software and confirmed harmless, so three weeks of alerts about it can be marked as expected. Beyond that: nothing indicates anyone got into our systems, no viruses were found, Firefox was updated and 20 of the 26 holes announced on 10 September are closed on both machines that had it. Monitoring coverage stayed good (13 lost connections, versus 121 three weeks ago). Root-level administrator use on the Macs eased back from 72 commands to 60.

The bad news. The remaining "act now" item has grown rather than shrunk: no safe-settings fix was observed on kmanwin11new or DAZWIN11, and Kman_Win_Old was scored for the first time and also came in under 30%, so three of five Windows PCs are now in that bracket. Six Firefox holes (4 critical) are still flagged; they probably need the next Firefox release rather than anything we did wrong.

Things to check. 9 wrong-password logins (7 of them on kman) and 15 user account changes (9 on DAZWIN11, 5 on Kman_Win_Old, 1 on tigswin10), both higher than last week. On kmanwin11new, 44 firewall filter rules were deleted in one go. The Macs' network chatter rose again to 1,226 port events (now known to be Apple services, so noisy rather than worrying), and one Mac shows the hidden temporary files of Apple's iPhone Simulator, which means developer tools (Xcode) are installed on it.

Software updates and known holes

Every piece of software has flaws. When one is discovered it gets a public reference number (a "CVE") and a severity rating, and the maker releases a fix. Our monitoring raises an alert when a new hole appears on a computer and another when it is closed.

Firefox: the fix worked, mostly. Last week's special report flagged 26 new Firefox holes. This week the monitoring recorded 20 of them closed, on two machines each, which means Firefox was updated where it mattered. Six are still flagged: CVE-2026-84140 to 84145, four rated critical and two high. These were not in the fixed list, which usually means the installed Firefox is now one release behind again, or Mozilla has not shipped that fix yet. Check Help → About Firefox once more this week; if it says up to date, there is nothing more to do until the next release.

Windows 10: resolved. tigswin10, with its 32 unfixable operating-system holes, has been removed from the network. This was the top item on every report so far, and closing it removes the single easiest way into the network. It will drop out of the device list from next week.

Windows 11 Pro: one medium-severity hole (CVE-2026-45585) is still flagged from last week. Windows Update should handle it.

Act now

Safe-settings checklist

Independent experts publish a checklist of recommended settings for each operating system (the "CIS Benchmark"). Our monitoring scores each computer against it and raises a summary alert whenever a machine is re-scored.

Three Windows PCs now score under 30%. Kman_Win_Old was assessed for the first time this week and produced six "score below 30%" summaries. kmanwin11new produced two more, so it has not improved from its 25%. DAZWIN11 was not re-scored this week; its last result was 26% and no setting was seen changing to "passed". The Mac tigs also produced a low-score summary, consistent with last week's 54%.

This is now the item with the biggest gap between effort and benefit. The fixes are the same ones listed since the first report: account lockout after wrong passwords, disable the Guest account, rename Administrator, turn off Remote Shell and basic authentication, enforce password history. They can be applied to all three machines in a single afternoon, and the score would visibly move the following week.

Exact percentages come from the compliance module reports (GDPR or TSC), which were not included this week; the NIST report only tells us which machines produced a below-threshold summary.

Viruses and hidden activity

The monitoring scans files against known virus signatures and looks for things a computer is trying to hide from its owner (a classic sign of a "rootkit").

No viruses were found and no hidden processes. The same three Macs reported hidden ports, led by port 55555 on Mac.lan (18 reports). This has now been checked and resolved: the port belongs to Apple's own macOS services and is not harmful. The monitoring flags it only because macOS does not list it the way the monitor expects. It should be added to the monitoring's expected list so it stops appearing, and the remaining scattered ports (63120, 51250) are the same class of Apple activity.

New: hidden files in Apple temporary folders. One Mac reported hidden files inside /var/tmp/com.apple.CoreSimulator... and several com.apple.launchd folders. CoreSimulator is Apple's iPhone Simulator, part of the Xcode developer tools, and launchd folders are macOS's own temporary storage. Both are normal for a Mac used for software development, and the monitoring flags them simply because it cannot see inside them. Not a threat, but it confirms developer tools are installed on that Mac, which is worth knowing.

Changes to files and system settings

Most of the week's events, and almost all of it is Windows housekeeping: backup snapshots, clock sync and app tracking constantly rewrite the settings database (the registry). About 3,600 registry alerts, down from 4,400. Two PCs (kmanwin11new and Kman_Win_Old) produced 2,100 of them; DAZWIN11 was much quieter than in previous weeks.

One change worth a question. On kmanwin11new, 44 entries were deleted from the Windows firewall's filter list in one batch. Windows Update and VPN or security software do this when they rebuild their rules, so it is probably routine, but firewall rules disappearing is also what an attacker does to open a path, so it earns a quick "was something installed or updated on that PC around then?"

The Macs' network chatter keeps rising: 1,226 port open/close events (881 last week, 262 the week before), led by tigs at 651 and Mac.lan at 537. This is the same Apple service as the now-resolved port 55555, so it is noise rather than a concern; the monitoring can be tuned to quieten it. Elsewhere, Windows system errors rose to 73 (from 20) and the system clock was adjusted 49 times, both consistent with a week that included updates and reboots.

Context

What the "compliance" report means

This week's bundle included one rulebook report, NIST 800-53. As before, it contains no new findings; the monitoring tags each alert with the rulebook clauses it relates to. Its real value to us is that it breaks alerts down per machine, which is how we know the failed logins were on kman and the account changes on DAZWIN11 and Kman_Win_Old. Almost every tag points back to routine registry changes (clause SI-7) and the Macs' port activity (AU-6 and AU-14).

Reference

Jargon, translated

Agent
A small program installed on each computer that reports back to the monitoring system. When it "disconnects", we lose sight of that computer.
CVE
A public reference number for a known software flaw, like a recall notice for cars. Each comes with a severity rating: critical, high, medium or low.
CIS Benchmark
An independent, widely-used checklist of recommended security settings for Windows and Mac. Reported as a percentage passed.
Firewall filter
One rule in Windows' built-in firewall saying what network traffic to allow or block. Software adds and removes them as it installs and updates.
Root / sudo
The all-powerful administrator account on Macs. "sudo" runs a command as root. Normal during installs and development work; unusual in bulk on an ordinary office Mac.
Xcode / CoreSimulator
Apple's software-development tools and the iPhone Simulator that comes with them. Their temporary folders are hidden by design.
Registry
Windows' internal settings database. Windows edits it constantly, which is why it generates most alerts.
Rootkit / hidden port
Software that conceals itself from the computer's own tools. "Hidden port" means a network connection the computer did not admit to.

How were the traffic lights decided?

The same fixed rules as every week: a finding an attacker could exploit directly today (unpatched critical or high holes; missing lock-out and open remote access) is "Act now"; findings that need a human to confirm they were intended are "Watch"; routine operating-system behaviour is "Fine". The judgement is ours, based on the counts in the reports.

What is not in these reports?

Email and phishing, cloud services, phones and tablets, backups, and the office router. A complete picture of the organisation's security would include those.
